# jf_hw_stress audit — 2026-10-31

Scope: `main` at `0e8f4a5` (v1.5.1): `jf_hw_stress.py` (3,010 lines), `pyproject.toml`, `.gitignore`.
Method: full read of the source, `py_compile` and `pyflakes`. Nothing was executed against ffmpeg: the tool
creates real transcode load, and the only hardware available here (Apple VideoToolbox on the home Mac) also
serves Jellyfin. Findings marked *needs hardware* are inferred from the ffmpeg command line and need a run on
that platform to confirm.

## Summary

The tool's idea is sound: it ramps Jellyfin-like HLS transcodes until frame rate drops, on real hardware. The
implementation has three kinds of problems:

1. **Merge damage.** The last merge duplicated code. As a result the program runs twice, the installed command
   ignores its flags, the HTML table is misaligned and every FPS sample is counted twice.
2. **Measurement errors.** The pass/fail signal uses ffmpeg's average frame rate since the stream started, not the
   current one. Log parsing gets slower the longer a test runs, which skews the benchmark itself. Read rate is shown
   8× too high.
3. **Untested backends.** The NVENC, QSV, VAAPI and AMF paths have never been checked against real hardware, and two
   of them build filter chains that are likely to fail.

There are no tests, no README, no license and no CI.

## Findings

Severity: **P1** wrong results or broken entry points; **P2** misleading output or fragile paths; **P3** polish.

### P1 — correctness

| # | Finding | Where | Effect |
|---|---|---|---|
| 1 | The `if __name__ == "__main__":` body is pasted twice | end of file | After a test finishes, the program parses the arguments again and starts a second full test (interactive or headless). |
| 2 | The `jf-hw-stress` entry point calls `main()`, which never reads arguments | `pyproject.toml`, `main()` | After `pip install`, `jf-hw-stress --headless …` opens the interactive TUI, and `--list-scenarios` doesn't work. Headless only works as `python3 jf_hw_stress.py`. |
| 3 | Pass/fail uses ffmpeg's `fps=` progress value, which is the average since that stream started (`speed=` is likewise cumulative) | `StreamManager.refresh`, `EscalatingController.tick` | A stream that slows down after minutes of good output keeps an average above the threshold for a long time. Failure is detected late or never, so "max stable streams" is overstated. Per-interval frame-count deltas are needed. |
| 4 | `parse_log` reads each stream's whole progress log five times a second | `parse_log` | `-progress` adds about 1.8 MB per stream per hour. After an hour with 10 streams, Python parses about 90 MB/s, and the tester competes with the encoders it is measuring. |
| 5 | ffmpeg children inherit the terminal's stdin | `StreamManager.launch` | ffmpeg reads keypresses meant for the TUI (`q` stops a stream, `?` prints help) and can change terminal modes. This is probably why `stty sane` runs at exit. Fix with `-nostdin` and `stdin=DEVNULL`. |
| 6 | Escalation keeps launching streams that fail immediately | `EscalatingController.tick` | Streams in `error` are left out of `active`, so the controller adds another one every ramp interval, indefinitely (interactive mode). A stream that fails to start should count as a failure. |
| 7 | The source isn't looped | `build_command` | When the file ends, streams become `done`. Interactive escalation then waits forever, and short sources end tests early. Jellyfin-style load needs `-stream_loop -1` (plus `-re` if real-time pacing is wanted). |
| 8 | HLG is classified as HDR10 | `probe_source` | `"bt2020" in primaries` is checked before the HLG transfer, and HLG always uses BT.2020 primaries. |

| # | Finding | Where |
|---|---|---|
| 9 | Each FPS sample is appended twice, and the stream-exit block is duplicated, so JSON `samples` and percentiles are wrong. | `refresh` |
| 10 | HTML stream rows have 13 cells under 9 headers; GPU, ffmpeg path, source path and cache directory are each shown twice; `_h = escape` and `_tail_log_error` are defined twice. | `generate_report` |
| 11 | Estimated read rate multiplies speed by **megabits**/s and labels it **MB/s**, so it is 8× too high. The write rate includes the progress logs as well as the segments. | `IOMonitor` |
| 12 | In Hybrid mode, the ENCODE line, the summary and JSON `config.encode_hw` show the platform rather than each stream (HW even after the switch to SW). Mixed mode reports `MIXED_SCENARIOS[0]` as "the scenario". | dashboard, summary, JSON |

| 14 | `tonemap_videotoolbox` (and zscale tone mapping) exist only in jellyfin-ffmpeg or builds with zimg. On a stock ffmpeg, HDR scenarios fail with a filter error instead of a clear message. | VT platform, `_SW_TM_*` |
| 15 | Scenarios ignore the source resolution: "4K → 1080p" on a 1080p file is a 1080p→1080p job, and Mixed mode upscales 1080p sources to 4K. Labels and results can mislead. | `SCENARIOS`, `MIXED_SCENARIOS` |

| 18 | HTML values taken from the media file (language tag, profile, pixel format, transfer) and the failure reason are inserted without escaping. A crafted file could inject markup into a report someone later opens or shares. | `generate_report` |
| 19 | The platform definitions are written out twice (`detect_all_hardware` and `_force_hardware_platform`) and have already drifted apart (GPU naming, the AV1 decode list). | hardware detection |
| 20 | Cache handling: the chosen directory is never removed, the last segments, playlists and logs are left behind, a custom path isn't validated, and any `st_*` file in it is deleted at start. macOS gets no RAM-disk option, and the default choice is the system temp folder on the internal SSD, which the prompt itself warns against. | `pick_cache_dir`, startup |
| 21 | `kill_all` never waits for its children (zombies until exit). SIGINT goes to the whole foreground process group, so Ctrl+C also kills every ffmpeg directly. Signal handlers aren't restored. | `kill_all`, `run_loop` |
| 22 | On Windows, `wmic` (used for GPU names) is removed in current Windows 11 builds, so GPU names come back as "GPU". | `_gpu_windows` |

### P3 — polish

- Duplicate imports and docstring lines; an f-string without placeholders; version 1.5 in `pyproject.toml` vs 1.5.1 in the code.
- `-g 48` is fixed whatever the frame rate; Jellyfin aligns keyframes to segments.
- `fps_history` grows without bound in continuous mode.
- No GPU or media-engine utilisation is measured, only frame rate. Optional sampling (nvidia-smi; intel_gpu_top; on macOS, powermetrics, which needs sudo) would explain *why* a limit was reached.
- No README, LICENSE, CHANGELOG, tests, CI or type checking. `pyproject.toml` has no classifiers, URLs or `py-modules`.

Not found: shell injection (every command is an argument list), network access, or credential handling.

## Proposed refactor (v2.0.0)

1. **Package layout** (`src/jf_hw_stress/`): `cli`, `tools` (ffmpeg discovery), `platforms` (one table that both
   auto-detection and `--force-platform` use, with capability checks), `probe`, `scenarios`, `command` (pure
   function: config → argv), `runner` (one reader thread per stream parsing `-progress` from a pipe, with
   instantaneous FPS from frame deltas), `controller`, `tui`, `reports/json`, `reports/html` (escaped template).
   Interactive and headless share one engine.
2. **Behaviour fixes:** P1 and P2 above. The JSON report stays backward-compatible and gains a `schema_version`;
   any changed meaning (for example instantaneous FPS) is documented.
3. **Tests:** unit tests for command building per platform, probe parsing from recorded ffprobe JSON, controller
   decisions on synthetic FPS series, report escaping. One integration test runs a few seconds of software encodes
   on ffmpeg's `testsrc` (no media file needed).
4. **CI:** GitHub Actions on Linux, macOS and Windows for Python 3.9–3.13: lint, type check, unit tests, and the
   software integration test on Linux.
5. **Distribution:** installable with `pipx install`, plus `python -m jf_hw_stress`.
6. **Docs (last):** README (what it measures and what it doesn't, install, quick start, modes, scenarios, platform
   support matrix with tested/untested status, cache-disk guidance, reading results, JSON schema, CI/Kubernetes
   usage, safety notes), CHANGELOG, CONTRIBUTING, LICENSE.

## Decisions needed from the owner

- **License:** the repository is public with no license, so by default nobody may reuse it. Two commits (via PR #1)
  are by ZoltyMat; choosing a license and telling them is the clean path.
- **Single file vs package:** one downloadable script is convenient. A package makes testing and maintenance practical.
  Both are possible: package as the source of truth, plus a generated single-file build attached to releases.
- **JSON compatibility:** keep the current headless JSON fields (someone may consume them in CI or Kubernetes) and
  add new ones; or allow a breaking v2 schema.
- **Hardware validation:** only VideoToolbox can be tested here, and only when nobody is streaming from this
  Jellyfin. NVENC, QSV, VAAPI and AMF would be documented as untested unless someone with that hardware runs the
  integration checks.
